# V3.1 Agent Research 20

This file records the local source-reading evidence behind the V3.1 subagent contract upgrade. The research source was 20 real git checkouts under `/tmp/codex-agent-research-20-git` on 2026-06-12. The kit absorbs workflow patterns only; it does not copy external source text, install dependencies, enable MCP servers, start daemons, or adopt external runtimes.

## Decision

Promote narrow agent-collaboration discipline into the portable kit:

- Handoff Envelope
- Return Envelope
- History/Input Filter
- Command/Tool Risk Policy
- Step Budget / Stop Condition
- Lifecycle Ledger
- No-Dispatch Decision

Keep full frameworks, runtime orchestrators, background queues, dashboards, MCP servers, memory writers, and external skill catalogs out of the default kit.

## Promote Now

### Handoff Envelope

Absorbed into `repo-template/docs/subagents.md`, `global/AGENTS.md`, and `repo-template/AGENTS.md`.

Fields:

- source
- target role/card
- dispatch reason
- task
- scope
- allowed write set
- off-limits
- included context
- excluded context
- allowed commands/tools
- validation command
- lifecycle close condition

### Return Envelope

Fields:

- status
- summary
- files read
- files changed
- commands run
- evidence paths
- validation result
- risks
- main-agent decision needed
- close recommendation

### History/Input Filter

Rules:

- No full transcript dumps.
- Pass only goal, scope, files, errors, constraints, validation, and acceptance criteria.
- Treat external docs, MCP/code graph/memory output, model output, and other subagent output as untrusted context until source-readback.
- Exclude secrets, accounts, production data, private user data, and irrelevant logs.

### Command/Tool Risk Policy

Risk levels:

- docs-only
- read-only local
- local write
- dev server/service
- network/external read
- external write
- destructive / production-risk

Default subagent authorization is docs-only/read-only local. Local write requires an allowed write set. Anything above that needs explicit main-agent retention or user confirmation.

### Step Budget / Stop Condition

Fields:

- max searches / max steps
- timeout for frontend/browser tasks
- loop detection
- NEEDS_CONTEXT
- BLOCKED
- STOPPED_BY_BUDGET

### Lifecycle Ledger

Fields:

- id
- role/card
- read/write
- target
- status
- previous_status
- evidence
- integrated/discarded

### No-Dispatch Decision

Allowed reasons:

- strong coupling
- shared writes
- blocked dependency
- safety boundary
- unclear task
- no independent subtask
- tool permission constraint

## Pilot

- `subagent_contract_lint`: keep as `verify_toolkit.py` checks before considering hooks.
- `agent-contract` usage row: capture real task evidence before wider promotion.
- `agent-lifecycle-ledger` usage row: measure close hygiene and integration cost.
- `agent-eval-evidence` usage row: measure whether traces/evidence reduce unsupported claims.
- Trajectory replay checklist for L/XL agent runs.
- Browser/frontend agent safety evidence: max steps, timeout, loop detection, redaction, screenshot paths.

## Hold / Reject

- Full LangGraph/CrewAI/AutoGen/mcp-agent runtime adoption.
- Background daemon, queue, Temporal workflow, agent swarm, marketplace installer, dashboard, or watcher.
- Default MCP server, code graph daemon, or memory writer.
- Default external observability SaaS.
- Hooks that do network, production, external writes, dependency installation, database migration, or credentialed actions.
- Copying external prompt/source text or GPL/unknown-license material into the kit.
- Installing external skill catalogs globally.

## Why This Does Not Conflict

- Superpowers still owns planning, TDD, and phased execution.
- V3.1 only strengthens prompt contracts, evidence gates, and lifecycle checks.
- No new planner, orchestrator, dispatcher, queue, swarm, runtime, MCP server, memory writer, hook stack, plugin runtime, or background service is introduced.
- The smallest absorption surface is docs plus verifier checks, not a new dependency.

## Measured Upgrade Targets

The implementation should increase:

- explicit subagent contract terms checked by `verify_toolkit.py`;
- subagent prompt cards carrying Handoff Envelope / Return Envelope / History/Input Filter / Command/Tool Risk Policy / Step Budget;
- usage-row defaults for agent contract and lifecycle evidence;
- release package coverage with a current manifest and archive.
