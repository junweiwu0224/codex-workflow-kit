# V3.2 Frontend Browser Video Workflow

This document records the V3.2 absorption of frontend design, browser automation, and product demo video workflows into Junwei's personal Codex workflow kit.

## Decision

The decision is to absorb useful workflow patterns from popular upstream components, but not to copy or globally install them.

吸收精华，不照搬:

- `junwei-frontend-design` becomes the design director layer for taste, mode routing, anti-template critique, and visual acceptance.
- `junwei-browser-automation` becomes the browser evidence and tool-routing layer for in-app Browser, Playwright CLI, repo tests, and Playwright MCP pilots.
- `junwei-product-demo-video` becomes the product demo video production layer for story, capture plan, scene review, render QA, and handoff.

## Sources Checked

- `microsoft/playwright-mcp`: primary GitHub README and Playwright docs. Evidence checked on 2026-06-22: `microsoft/playwright-mcp`, 34,168 stars, 2,836 forks, Apache-2.0, pushed 2026-06-20; README shows Node.js 18+ requirement, `npx @playwright/mcp@latest`, structured accessibility snapshots, and explicit guidance that coding agents may prefer `CLI+SKILLS` for context efficiency while MCP remains useful for persistent state and rich introspection.
- `digitalsamba/claude-code-video-toolkit`: primary GitHub README, CLAUDE.md, releases, and optional component docs. Evidence checked on 2026-06-22: `digitalsamba/claude-code-video-toolkit`, 1,553 stars, 266 forks, MIT, pushed 2026-06-19; README shows an AI-native video production workspace with Remotion, FFmpeg, Playwright recording, scene/review workflows, setup wizard, cloud GPU providers, voice configuration, and publishing-oriented flows.
- Existing local frontend guidance: `frontend-qa`, global browser routing, and Junwei's desired long-term personal frontend skill.

Evidence quality: strong for source capabilities and local fit; medium for long-term efficiency until repeated real product tasks accumulate more usage rows.

## Intake Review

`microsoft/playwright-mcp`:

- Decision: pilot, not default install.
- Worth absorbing: structured page inspection, accessibility snapshots, persistent browser state, exploratory interaction, self-healing inspection loops.
- Not absorbed: default MCP config, always-on server, broad browser state access, default `npx` fetches, production mutation.
- Loading budget: library/pilot.

`digitalsamba/claude-code-video-toolkit`:

- Decision: inspiration and repo-local pilot, not default global install.
- Worth absorbing: project lifecycle, product truth, browser demo capture, Remotion/FFmpeg composition model, scene review, brand/audio/render QA.
- Not absorbed: `/setup`, cloud GPU deployment, API key setup, voice cloning, external storage, YouTube or social publish, vendored toolkit code.
- Loading budget: library/pilot.

Frontend design sources:

- Decision: promote as active personal skill.
- Worth absorbing: product-grounded art direction, one distinctive design bet, anti-generic critique, mode-specific UI guidance, browser/mobile verification discipline.
- Not absorbed: broad landing-page bias, decorative defaults, any copied third-party prose.
- Loading budget: daily.

## Role Separation

Use each skill for its own job:

| Local browser inspection, Playwright routing, MCP evaluation, demo capture input | `junwei-browser-automation` | `frontend-qa`, `security-review` |
| Demo story, scene plan, browser recording plan, render QA | `junwei-product-demo-video` | `junwei-browser-automation`, `dependency-upgrade-review` |
| External component absorption | `research-brief`, `skill-plugin-intake-review` | `security-review` |
| Portable release/package evidence | `release-readiness` | `completion-review` |

## No-Conflict Matrix

- Frontend design without video: use `junwei-frontend-design`; verify with `frontend-qa` or project tests.
- Browser automation without design change: use `junwei-browser-automation`; do not trigger a visual redesign.
- Product demo video from UI: use `junwei-product-demo-video` for story and render; call `junwei-browser-automation` only for capture inputs.
- Playwright MCP evaluation: use `junwei-browser-automation` and keep MCP as a reversible pilot with rollback.
- New video dependencies or lockfile changes: use `dependency-upgrade-review`.
- Sensitive browser state, auth, recordings, cloud services, publishing, or MCP/plugin trust boundaries: use `security-review`.

## Security review

Scope: packaged skills, references, docs, and workflow routing.

No issue found:

- No MCP server is installed or configured by default.
- No `codex mcp add playwright`, `~/.codex/config.toml` edit, daemon start, browser dependency install, cloud GPU deployment, API key setup, voice cloning, upload, or publish path is added.
- The skills explicitly stop at production mutation, billing/account changes, private data scraping, cloud services, paid APIs, customer data, secrets, recordings with sensitive data, and external publishing.
- The package contains workflow instructions and references only; it does not vendor upstream source code or credentials.

Residual risk:

- Any future Playwright MCP pilot can expose browser state and tool execution surface; it must record config, permission surface, step budget, auth/session source, and rollback.
- Any future video production repo-local pilot can introduce heavy dependencies, generated media, cloud cost, or sensitive recordings; use `dependency-upgrade-review` and `security-review`.

## Expected Positive Effect

正向效果:

- Fewer generic AI-looking frontend outputs because design direction is explicit before implementation.
- Less browser-tool thrash because in-app Browser, Playwright CLI, repo tests, and Playwright MCP have a clear routing order.
- Safer demo video work because story/capture/render QA is separated from cloud/API/publish setup.
- Lower global workflow risk because high-value external ideas are distilled into narrow personal skills rather than installed as always-on tools.

## Non-Goals

- Do not make Playwright MCP a default Codex MCP server.
- Do not install DigitalSamba globally.
- Do not replace `frontend-qa` with design taste.
- Do not replace Superpowers planning/TDD/execution.
- Do not turn product demo work into automatic external publishing.
