# V3.1 Adoption Evidence

This file records the V3.1 portable workflow kit evidence. It is intentionally about the current V3.1 package surface, while `docs/V2-ADOPTION-EVIDENCE.md` remains historical adoption evidence.

## Core Semantics

- `promote != install`: promotion means absorbing a rule, checklist, read-only script, prompt card, narrow skill, or repo-template boundary. It does not install or enable external components.
- `pilot != enable`: pilot means baseline, scope, permission level, exit condition, and rollback are documented. It does not default-enable a tool.
- `core != runtime/background`: V3.1 Core is rules, boundaries, prompt cards, read-only review, and narrow skills; it is not a default runtime.
- Approved docs/script does not approve external write, production write, account operations, credentials, browser state, or destructive actions.

## External Component Intake

- `docs/external-component-intake.md` defines scores, risk tags, loading budgets, decisions, and reject lines.
- `scripts/audit_external_component.py` provides read-only local audit for skills, plugins, MCP configs, hooks, install scripts, private paths, secrets, curl-to-shell, daemons, network, auth, write surfaces, and Superpowers overlap.
- `skills/skill-plugin-intake-review/SKILL.md` keeps review narrow: decide promote / pilot / repo-local / hold / reject before absorption.

## Code Graph Pilot

- `repo-template/docs/codegraph-pilot.md` keeps code graph as orientation, not a truth source.
- Default baseline remains `rg`, `rg --files`, language tools, tests, context pack, and source readback.
- There is no default MCP code graph server, no default index daemon, and no default cloud service.

## Memory Recall Pilot

- `repo-template/docs/memory-recall-pilot.md` keeps repo facts in repo docs first.
- There is no default memory hook and no default MCP memory writer.
- Recall requires provenance and must not store raw transcript, logs, secrets, production data, or private user data.

## Hook Discipline

- `repo-template/docs/quality-gates.md` adds Hook Review Checklist, advisory/fail-open first-run mode, External Component Gate, and no default hook stack.
- Blocking hooks remain limited to fast, deterministic, local, low-false-positive, no-network, no-credential, no-business-data-write checks.

## Subagent Prompt Cards

- `repo-template/docs/subagents.md` adds the V3.1 Prompt Contract with `allowed write set`, `off-limits`, verification, output format, and lifecycle close.
- Agent Research 20 is recorded in `docs/V3.1-AGENT-RESEARCH-20.md`; it summarizes 20 real git checkouts and the promote / pilot / hold / reject decisions behind the subagent contract upgrade.
- `repo-template/docs/subagents.md` now requires Handoff Envelope, Return Envelope, History/Input Filter, Command/Tool Risk Policy, Step Budget / Stop Condition, Lifecycle Ledger, and No-Dispatch Decision.
- Prompt cards cover read-only code mapper / explorer, implementation worker, coverage-gap auditor, test/debug investigator, batch worker, frontend QA reviewer, docs/content-contract reviewer, and architecture/migration reviewer.
- Main agent remains responsible for integration, diff review, final verification, and subagent lifecycle close.
- `scripts/benchmark_agent_contract.py` measures the upgrade from pre-agent-contract `2026.06.12.1` to the current package.
- `docs/agent-collaboration-smoke.md` adds a manual/HITL runtime smoke checklist for read-only dual explorer, No-Dispatch Strong Coupling, Local-Write Boundary, Visibility Policy, Skill Coupling, Return Envelope review, and Lifecycle Ledger close evidence.

## Runtime Evidence Layer

- `scripts/codex_runtime_smoke.py` splits local runtime evidence from package integrity: it summarizes live install, local doctor, Codex CLI, optional `codex debug prompt-input`, and the manual `docs/agent-collaboration-smoke.md` checklist.
- `scripts/audit_skill_contracts.py` audits the packaged skills for metadata, trigger clarity, Output Shape, boundaries, validation, progressive disclosure, and Superpowers overlap signals.
- Package verification remains `scripts/verify_toolkit.py`; runtime smoke and skill contract audit are separate evidence layers so package checks do not pretend to prove interactive subagent behavior.

## Real Usage Calibration

- `docs/codex-usage.md` records eight real M/L V3.1 trials in this toolkit repository: the first four cover trial-row helper, runtime smoke / skill audit evidence, package verifier coverage, and release-readiness drill; the closeout four cover release evidence alignment, trial preset helper, package/docs contract alignment, and release-readiness closeout.
- `scripts/render_usage_row.py trial` renders repeatable real-task rows with `Positive Signal`, `Friction`, and `Decision` cells so usage evidence is not hand-written from memory.
- `scripts/render_usage_row.py trial --preset` reduces repeated closeout flags while remaining render-only; it does not auto-append docs or promote rules.
- Current decision: keep `verify_toolkit.py`, `codex_runtime_smoke.py`, `audit_skill_contracts.py`, `release-readiness`, and `render_usage_row.py trial --preset`; keep No-Dispatch, Local-Write Boundary, and Visibility Policy as manual/HITL checklist cases.

## Agent Self-Diagnosis

- `skills/debug-loop/SKILL.md` covers `goal drift`, `context drift`, `unsupported claim`, tool loops, verification gaps, and subagent lifecycle recovery.
- `skills/completion-review/SKILL.md` requires evidence for completion claims and a final subagent lifecycle check before delivery.

## Skill Polish

- `skills/debug-loop/SKILL.md` strengthens Feedback Loop First: failing test, captured trace replay, property/fuzz loop, regression test, deterministic loop, and explicit Output Shape.
- `skills/completion-review/SKILL.md` adds an Artifact / Release Evidence Gate for archive listing, checksum, install docs, manifest, release evidence, and Output Shape.
- `skills/frontend-qa/SKILL.md` adds accessibility coverage for Keyboard, Focus, Contrast, ARIA, and Reduced motion checks.
- `skills/decision-record/SKILL.md` adds Output Shape and Completion Conditions for ADR quality and Superseded handling.
- `skills/repo-onboarding/SKILL.md` separates minimal context pack from optional context pack so onboarding does not create every doc by default.
- `skills/spec-kit-xl/SKILL.md` now points to `references/spec-template.md` for progressive disclosure instead of carrying the full template inline.
- `skills/release-readiness/SKILL.md` is a pilot skill for reusable artifact, portable toolkit, release archive, checksum bundle, install drill, rollback, and release evidence checks.
- `scripts/benchmark_skill_polish.py` measures the skill polish delta against the pre-polish `2026.06.12` release.

## Reject Lines

V3.1 explicitly keeps these out of the portable default:

- no default MCP server
- no default memory writer
- no default hook stack
- no default code graph daemon
- no default plugin runtime
- no default dashboard or watcher
- no new orchestrator, planner, dispatcher, queue, marketplace installer, or agent swarm
- no restored `implementation-plan`
- no bulk external skill/plugin/catalog install
- no automatic PR, ticket, deploy, production write, account, permission, payment, key, or secret operation
- no auto-learned global rules or automatic hierarchical memory files
- no GPL/unknown license source text copied into the portable kit
