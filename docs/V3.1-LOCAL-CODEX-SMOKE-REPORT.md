# V3.1 Local Codex Smoke Report

- Date: 2026-06-13
- Host scope: `<toolkit-root>`
- Codex CLI: `codex-cli 0.140.0-alpha.2`
- Toolkit version under test: `2026.06.13.1`; smoke began from `2026.06.12.3` and added runtime evidence / skill contract audit tooling plus real-usage calibration.
- Goal: verify how V3.1 skills and subagent protocol work together on this local Codex install, then identify next optimization work.

## Executive Summary

V3.1 is usable on this machine as a portable workflow kit: the packaged custom skills match the live install, the local workflow doctor passes, the model-visible prompt input includes the expected skills, and real subagent runtime operations can spawn, return, and close read-only explorers.

The strongest remaining gap is enforcement depth. Current package checks prove file presence, contract text, benchmark coverage, and installation drift. They do not automatically prove that every real subagent run follows the Handoff Envelope, Return Envelope, lifecycle ledger, and close hygiene unless the main agent prompts, reviews, and closes explicitly.

During smoke testing, one real packaging bug was found and fixed: running `scripts/codex_doctor.py` directly generated `scripts/__pycache__/verify_live_install.cpython-312.pyc`, which made `scripts/verify_toolkit.py` fail. The fix disables bytecode writing while `codex_doctor.py` imports `verify_live_install.py`, and a regression test now locks that behavior.

The follow-up optimization added two reusable evidence scripts plus a manual runtime checklist:

- `scripts/codex_runtime_smoke.py` keeps live install, local doctor, Codex CLI, optional prompt-input skill visibility, and manual agent smoke evidence separate from package integrity.
- `scripts/audit_skill_contracts.py` verifies that all 11 packaged skills expose metadata, trigger, Output Shape, boundary guidance, and validation signals.
- `docs/agent-collaboration-smoke.md` records the manual/HITL cases that cannot be honestly proven by portable package scripts.

## Bug Found And Fixed

Symptom:

```text
Workflow toolkit issues: 3 error(s), 0 warning(s)
[error] generated-bytecode-present scripts/__pycache__/verify_live_install.cpython-312.pyc
[error] generated-cache-present scripts/__pycache__
[error] private-home-path scripts/__pycache__/verify_live_install.cpython-312.pyc
```

Root cause:

`scripts/codex_doctor.py` imports `verify_live_install.py`. When run directly as a script, Python wrote bytecode into `scripts/__pycache__`. The package verifier correctly treats generated caches as release blockers.

Fix:

- `scripts/codex_doctor.py` now disables bytecode writing while importing `verify_live_install.py`.
- `tests/test_codex_doctor.py` adds a CLI regression test that copies `codex_doctor.py` and `verify_live_install.py` into a temporary toolkit, runs the doctor, and asserts no `scripts/__pycache__` is created.

Verification:

```text
python3 -m pytest tests/test_codex_doctor.py tests/test_verify_live_install.py -q
# 9 passed

python3 scripts/codex_doctor.py
# Codex doctor OK
# - live_install: OK
# - active_plugin_paths: OK
```

## Gaps

1. Runtime envelope enforcement is manual. The toolkit documents Handoff Envelope, Return Envelope, lifecycle close, and ledger fields, but the multi-agent tool does not enforce those fields automatically.
2. No-dispatch behavior was not tested live. This run focused on successful read-only dispatch and close, not the strong-coupling case where the main agent should explicitly decline delegation.
3. Local-write worker boundaries were not tested. No worker was given a temporary allowed write set, so write-scope enforcement remains unproven.
4. Subagent UI visibility was not tested. This run intentionally closed agents after collecting results. Historical context suggests immediate close can reduce user inspectability, so visibility needs its own smoke.
5. Official `codex doctor --json` currently fails on `terminal.env` because this shell reports `TERM=dumb` and `NO_COLOR=1`. This does not block V3.1 skills/agents, but it means raw official doctor output should be interpreted by check category, not only by top-level status.
6. Superpowers child-skill visibility was not directly verified. Current visible custom skills complement Superpowers, but `dispatching-parallel-agents` / `subagent-driven-development` were not observed as explicit entries in the current prompt input.

## Recommended Optimizations

Status after `2026.06.13.1`: the P0/P1 package-side optimizations below have been implemented as scripts, docs, tests, release evidence, and real-usage calibration. Interactive enforcement remains intentionally manual/HITL because the multi-agent runtime is not a portable repo API.

### P0: Add Live Agent Collaboration Smoke

Add a manual or semi-automated checklist named `agent-collaboration-smoke`:

- dispatch two read-only explorers with disjoint questions;
- require Handoff Envelope and Return Envelope;
- record agent ids, wait result, integrated/discarded decision, and close result;
- verify `close_agent` returns a completed `previous_status`;
- record a final lifecycle ledger row.

This should remain a manual/HITL smoke at first because the actual multi-agent tool is outside the portable repo scripts.

Implemented as `docs/agent-collaboration-smoke.md`.

### P0: Split Package Checks From Runtime Checks

Keep `scripts/verify_toolkit.py` focused on portable package integrity. Add a separate runtime evidence section or script wrapper for:

- `python3 scripts/verify_live_install.py`;
- `python3 scripts/codex_doctor.py`;
- `codex debug prompt-input 'List available skills briefly'`;
- official `codex doctor --json` category summary with known terminal caveats;
- optional subagent smoke checklist output.

This avoids making package verification pretend it has proven live runtime behavior.

Implemented as `scripts/codex_runtime_smoke.py`.

### P1: Add Skill Contract Audit Matrix

Add a read-only `scripts/audit_skill_contracts.py` that outputs a matrix for each skill:

- trigger clarity;
- setup/auth/network/write-surface metadata;
- boundaries / do-not-do rules;
- Output Shape;
- verification or completion conditions;
- progressive-disclosure references;
- overlap risk with Superpowers.

Ampere independently recommended this, and it would reduce manual `rg` work.

Implemented as `scripts/audit_skill_contracts.py`.

### P1: Add No-Dispatch And Local-Write Boundary Smokes

Use two explicit fixture tasks:

- strong-coupling same-file task should produce a No-Dispatch Decision;
- local-write worker task should allow writes only to a temporary allowed write set, followed by main-agent diff review.

These should be recorded in `docs/codex-usage.md` or this report's successor.

### P1: Document Subagent Visibility Policy

Clarify two modes:

- close immediately when the subagent result has been integrated and user inspectability is not required;
- leave open until the user checks it when visibility/reviewability is part of the task, then close before final lifecycle completion.

This resolves the tension between clean lifecycle hygiene and user-visible subagent replies.

### P2: Normalize Official Doctor Interpretation

Add a small documented rule or helper summary that treats official `codex doctor --json` as category evidence. In this environment, terminal failures can make the top-level status fail even while config, auth, custom provider reachability, multi-agent feature flags, state DBs, plugin paths, and search are healthy.

## Next Concrete Work

The highest-leverage remaining work is deeper interactive runtime evidence: run the checklist cases for No-Dispatch Strong Coupling, Local-Write Boundary, and Visibility Policy on real bounded tasks, then record the results in `docs/codex-usage.md` or a successor smoke report.

Do not add a new orchestrator, planner, dispatcher, queue, or background runtime. V3.1 should stay document-first and evidence-driven: package checks for package integrity, runtime smoke for local Codex behavior, and subagents only where the task actually benefits from bounded parallelism.
