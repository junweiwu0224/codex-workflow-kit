# 当前任务授权检查

文件名为兼容旧路由保留。它不预先授权任何目标，也不能覆盖平台、组织、供应商、
系统或用户规则。

## 目的

在主动安全操作前，把当前任务的授权事实转成可审计的 Task Contract。历史项目、
相似目标、域名/IP 的出现、用户角色或本文件本身都不是授权证明。

## 最小授权记录

至少记录：

| 字段 | 要求 |
| --- | --- |
| 目标 | 明确域名、IP、应用、文件、租户或实验环境 |
| 所有者/授权方 | 能够批准该范围的主体 |
| 允许技术 | 只读分析、扫描、利用验证等逐项说明 |
| 禁止技术 | 拒绝服务、持久化、数据导出等边界 |
| 时间窗口 | 开始、结束和时区 |
| 数据处理 | 可访问、保存、脱敏和删除规则 |
| 外部副作用 | 网络、写入、安装、服务、生产变更 |
| 批准状态 | 当前批准者或用户明确授权的事实 |
| 停止条件 | 越界、异常影响、敏感数据或不确定性 |

## 执行规则

1. 本地样本的只读静态分析通常可以在工作区范围内继续。
2. 对外部目标的主动请求必须匹配明确目标与允许技术。
3. 安装工具、修改客户端配置、启动监听服务和外部写入分别审批，不做捆绑推断。
4. 批准缺失或含糊时，保持只读并请求必要信息。
5. 一旦观察到越界目标、生产影响、意外敏感数据或不可逆风险，立即停止并升级。
6. 不把一次任务的批准自动延续到另一个任务、目标或时间窗口。

## 与先例文件的关系

`precedent-reverse.md` 和 `precedent-pentest.md` 只记录历史方法和验证思路。
它们可以帮助选工具，但不能证明当前任务已获批，也不能取消确认或安全审查。

Task Contract 与当前上位政策冲突时，以更严格的边界为准。
