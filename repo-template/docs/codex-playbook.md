# Codex Playbook

本文件记录 Codex 在当前仓库工作的长期有效经验。不要重复 `AGENTS.md` 的硬规则，不记录一次性过程细节。

## 什么时候读这个文件

Codex 在以下情况应阅读本文件：

- 第一次处理本仓库中的中大型任务。
- 涉及多个模块、测试策略、前端视觉验证、构建配置或高风险区域。
- 之前在本仓库出现过误判、漏测、错误修改或重复踩坑。
- 用户要求“按本项目惯例处理”。

## 记录规则

只记录满足以下条件之一的内容：

- 已经在本仓库重复出现或可能重复出现。
- 能明显减少未来误判、漏测、返工或沟通成本。
- 是本仓库特有的工作方式，而不是通用 Codex 原则。
- 暂时还不适合放入 `AGENTS.md`、`docs/testing.md`、`docs/architecture.md` 或 ADR。

不要记录：

- 一次性过程细节。
- 普通调试流水账。
- 已经写入其他正式文档的规则。
- 过期命令、过期路径、过期架构说明。
- 泛泛的 prompt 技巧。

## 验证选择经验

- 先判断验证命令副作用等级：A 级无写入命令可默认跑；B 级报告命令要确认输出目录已忽略；C 级应用生命周期命令要确认本地 DB、缓存、调度器、端口和报告影响；D 级外部服务/数据写入命令需用户确认。
- Health check 不一定低副作用；如果它启动 app/TestClient/dev server，先阅读脚本和 docs，再决定是否运行。
- Compile/typecheck/lint 也不一定低副作用；确认是否写 bytecode、cache、coverage、build 产物或自动格式化文件后，再决定是否进入 hooks。

## 项目特定提示词

只记录经过验证、长期有效的 prompt。不要堆积普通提示词。

### 示例：任务规划

```text
先阅读 AGENTS.md、docs/architecture.md 和 docs/testing.md，定位相关模块，给出最小实现计划和验证方式。
```

### 示例：Review

```text
按 AGENTS.md 和 docs/testing.md 审查这个改动，重点看回归、安全、测试缺口和是否符合项目模式。
```

## 晋升和清理

- 如果一条经验已经稳定适用于所有任务，晋升到 `AGENTS.md`。
- 如果一条经验描述架构事实，晋升到 `docs/architecture.md`。
- 如果一条经验描述验证方式，晋升到 `docs/testing.md`。
- 如果一条经验是重要技术取舍，晋升到 `docs/decisions/`。
- 如果一条经验过期、重复、只适用于一次性任务，删除它。
