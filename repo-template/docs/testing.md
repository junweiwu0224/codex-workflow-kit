## 验证副作用分级

记录每条常用验证命令的副作用，避免把高副作用命令误放到 hooks 或默认自动门禁。

| 等级 | 说明 | 适合场景 | 示例 |
|---|---|---|---|
| A：无写入/低副作用 | 不访问外部服务，不写业务数据，不启动长期服务 | 默认 Codex 验证、hooks 候选 | context pack verifier、lint、类型检查、针对性纯单元测试 |
| B：写 ignored 报告 | 只写 `test-results/`、coverage、trace、截图等已忽略产物 | 人工触发、标准交付门禁 | 静态前端渲染风险报告、覆盖率报告 |
| C：触发应用生命周期 | 启动 app/TestClient/dev server，可能初始化本地 DB、调度器、缓存或端口 | 人工确认后运行，不放入无副作用 hooks | API health audit、browser smoke、preview server |
| D：外部服务/数据写入 | 访问网络、凭证、外部 API、数据库迁移、真实数据同步、生产/交易动作 | 用户明确确认后运行 | E2E 外部联调、数据同步、部署、迁移、实盘/支付/权限操作 |
 
如果一个命令看起来是 health check，也要检查它是否触发应用 lifespan、后台任务、本地数据库初始化或报告写入。

如果一个命令看起来是编译/语法检查，也要确认它是否写 bytecode、cache、coverage、build 目录或其他生成物；写入 ignored 产物时不要标成严格无写入 hook。

## Codex 验证原则

- 优先跑与改动最相关的最小验证。
- 影响共享逻辑、用户可见行为、安全、数据、构建配置时，升级到更全面验证。
- 选择验证前先判断副作用等级；默认自动门禁只放 A 级，B/C 级需要明确记录产物或生命周期影响，D 级需要用户确认。
- 验证失败后先判断是否由当前改动引起，再修复。
- 无法验证时，在最终回复中说明原因和风险。
