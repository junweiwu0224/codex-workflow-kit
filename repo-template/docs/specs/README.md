# Specs

本目录存放大型、长期、跨模块或高风险任务的规格说明。

## 什么时候新增规格

- 新功能区域、平台改造、架构迁移或大范围重构。
- 需求需要多轮讨论、长期验收标准或团队审查。
- 涉及 API、数据模型、权限、安全、性能、发布、迁移或回滚。
- 用户明确要求 spec、PRD、验收标准或 spec-kit。

日常 bug fix、小型功能、单文件改动不要强行写规格。

## 推荐流程

1. 用 `spec-kit-xl` 起草规格，明确目标、非目标、需求、验收标准和风险。
2. 规格状态达到 `Accepted` 后，用 Superpowers 写实现计划。
3. 实现完成后，用规格中的验收标准做最终验证。
4. 如果执行中发现规格错误，先更新规格，再继续计划或实现。

## 命名

推荐文件名：

```text
YYYY-MM-DD-短名称.md
```

示例：

```text
2026-06-07-admin-permissions.md
```

## 状态

- `Draft`：正在起草，允许有 `待确认`。
- `Review`：需要用户、团队或后续 agent 审查。
- `Accepted`：范围和验收标准已确认，可以进入计划。
- `Planned`：已有实现计划。
- `Implemented`：已实现并按验收标准验证。
- `Superseded`：被新规格替代，需链接替代文档。
